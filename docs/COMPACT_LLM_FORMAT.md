# Короткий формат ответа локальной LLM

Экспериментальный режим `compact` сокращает число выходных токенов. Модель возвращает
построчные факты; FitWeaver превращает их в размеченный план, а затем в Garmin YAML.
Индексы повторов и YAML модель не пишет. Режим доступен через
`garmin-fit-llm-eval --output-format compact`, `garmin-fit-llm --output-format compact`
и в экспертных настройках локальной LLM в GUI. По умолчанию остаётся `yaml`, пока
парное сравнение на golden-наборе не покажет достаточное качество.

```text
W|14.04.2026|Интервалы
S|warmup|2km|-
R|4
S|active|800m|pace:4:20-4:30
S|recovery|400m|-
E
S|cooldown|1km|hr:до 140
```

- `W|дата|название`: начало тренировки; `-` вместо даты, если её нет в источнике.
- `S|роль|объём|цель`: один шаг. Роли `warmup`, `active`, `recovery`, `cooldown`.
  Объём: `2km`, `400m`, `20min`, `90s` или `-`. Цель: `-`, `hr:130-145`,
  `hr:до 140`, `hr:Z2`, `pace:4:50-5:00`, `pace:5:50`, `cad:175-185`.
- `R|число`: начало повторяемой группы; `E`: конец. Группы могут быть вложены.
- `B|название:секунды:повторы;другое упражнение:секунды:повторы`: блок СБУ.

Синтаксис проверяется строго, затем применяется обычная схема и проверка Garmin
YAML. Неполный ответ, неизвестная команда или незакрытый повтор отклоняются.
Отсутствующие измерения и цели не додумываются. Файл
[`compact_plan.gbnf`](../src/garmin_fit/llm/compact_plan.gbnf) ограничивает синтаксис
на `llama-server`; сервер принимает GBNF в поле `grammar` completion-запроса,
см. [официальное руководство llama.cpp](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md).
Грамматика пока не проверялась живым `llama-server`; Ollama не использует этот файл.
